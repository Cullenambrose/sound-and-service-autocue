# Native indexed-folder and file evidence

Open **Library → Detailed workspace → Review indexed folders and ingestion records**. This uses the existing indexed-root and Studio inbox services; it does not enumerate an unselected folder or inspect Serato's library. The panel starts collapsed and reads evidence only when opened or explicitly refreshed.

Folder state comes from the backend's current directory/device/inode check. A missing or replaced folder is offline. The published scan revision and retained file records remain visible. File availability and metadata are the last published index evidence, not a fresh byte/hash verification; export and audition retain their separate current-source checks. A failed refresh displays an error and retains the previous snapshot with its last-check timestamp.

The inbox loads up to 100 records, prioritizing new records and then changed time. Overall counts can exceed the number loaded. Folder, title/artist/path and file-state filters operate only on this loaded scope, not the entire library. Use the separate catalog search for indexed music searches; there is no inbox pagination in this slice.

Views include all loaded records, title/artist gaps, any missing metadata, indexed unavailable files, indexed errors and same-hash groups. A file without a title uses its filename as a display label; that label is not written back as a tag. Title/artist gaps remain visible even when search excludes those files. Artist/title strings are displayed literally. Same-hash group membership is evidence, not a deletion or keeper decision. No review status, tag, source file, folder association or monitor setting is changed by this panel.

Visible active scan jobs now offer **Request cancellation**. The scan panel separates all returned active jobs from inactive history, so active jobs cannot be hidden behind five newer completed records. Inactive history starts at five rows and can be expanded/collapsed. The existing service returns all active jobs plus up to 20 recent inactive jobs; this is not complete historical pagination. The existing backend receives the selected job ID and current dataset ID. The native client verifies that the affirmative receipt identifies that exact job and reports cancellation pending or a terminal state; mismatches remain unconfirmed. Jobs can finish before cancellation is recorded, in which case a completed receipt is valid. The UI refreshes job status after the request. Cancellation changes only job state through the established API; it does not remove source media. There is no new endpoint, request schema or alternate scanning implementation.

This advances native library/ingestion visibility. Full-library inbox pagination, tag repair, reassociation, review-state changes, opt-in monitor controls, duplicate keeper workflows and physical external-drive acceptance remain future work. Testing uses temporary folders and generated audio; do not point development at the DJ laptop's real library. See `DEVELOPMENT-HANDOFF.md`.
