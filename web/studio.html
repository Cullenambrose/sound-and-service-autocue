    2. Plan an entire set
    
      
    Uses the current search rule and shared event matcher. Full-track duration is not mixed elapsed time. Unknown durations cannot prove a target.
    
      
    
        Translate a timed set brief with local AI
        
        
        
        
    Requires your existing local model. Review the translated draft first.
          Defaults when unspecified: 3-minute global tolerance, 20 tracks maximum,
          1-minute tolerance per phase. No library data or file IDs are sent.
    
        
    
        
        
    Applying replaces unsaved search/timing preferences. It retains source scope,
          existing event lists, global exact-file must-plays, exclusions and pins.
          Schedules containing phase-specific exact must-plays must be edited manually.
          Saved crates are never changed. Generation and approval remain separate.
    
      
    
      
    
        
    
          
          
    Each request uses title, artist and optional version. Do Not Play wins. Resolve ambiguous or unavailable must-plays first.
    
        
    
          
          
    IDs are exact file IDs from search. Pins use {"position":0,"file_id":"..."}.
          Optional bpm_min, bpm_max and energy_target are explicit requirements/preferences.
    
      
    
      
    
        Build an ordered phase schedule
        
    Every phase needs at least one full track and its own duration tolerance.
          Phase constraints add to global constraints; they never weaken them.
          Energy targets are preferences, not audible-quality guarantees.
          Apply explicitly to the policy below before generating alternatives.
    
        
        
        
        
    
        
    Targets/tolerances in this editor use tenths of a minute. Exact must-play IDs
          come from search. Advanced policies can still be edited directly as JSON.
          Applying sets the global target to the sum of phase targets, keeping its
          tolerance, exclusions, must-plays and pins unchanged.
    
      
    
      
    
        Reviewed play windows and transition evidence
        
    Optional timing overlay, not a change to full-track phase feasibility.
          Inspect the existing cues for each exact file, audition it yourself, and
          supply explicit entry/exit seconds with its indexed content hash.
          Mark reviewed only after your own review. Specify each adjacent overlap,
          including zero for an intentional cut. Missing evidence leaves mixed elapsed time unavailable.
    
        
        
        
    Window: {"file_id":"...","content_hash":"...","entry_s":0,"exit_s":120,"reviewed":false}.
          Overlap: {"from_id":"...","to_id":"...","seconds":0}.
          No speed changes, loop extensions, padding or automatic vocal/phrase safety are assumed.
    
      
    
      
    
      
    Isolated Live next-song suggestions
        
    Manual inputs only, no deck connection. Suggestions never modify saved Prep or play history.

      4. Indexed health and explicit play history
      
      
      Reports describe the published index, not fresh disk availability. Identical hashes prove whole-file bytes only. Related edits are not disposable duplicates. No cleanup or move action is enabled.
      
      
      
      
      Database recovery
      
      
      This private backup contains saved app state and indexed evidence, not audio,
        exported ZIPs or browser pending actions. Restore only into a new data directory
        using the documented Studio command; the active library is never overwritten.
      
      
      
      Acquisition inbox and selected-folder monitoring
      
      
      New or changed indexed evidence returns to the inbox. This is not a download service.
        Enabled monitors poll only your explicitly indexed roots while Studio runs.
        Scans reuse unchanged files; they do not analyze, move or copy original audio.
        Review metadata/versions yourself; inbox review is not event fulfillment.
      
      
      
      
      
      Recoverable Studio exclusions
      
      
      Exclusion hides an exact hash-bound file from new Studio searches/plans only.
        It does not delete/quarantine audio, repair DJ references or alter saved crates.
        Changed bytes invalidate an old exclusion. Restore below to undo.
